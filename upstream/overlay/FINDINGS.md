# Chatwoot bugs and quirks found while writing tests

Writing tests for every line of Chatwoot turns up behaviour that looks wrong. The tests pin Chatwoot's behaviour as
it is (so the reference stays honest), and each case is listed here so the Laravel/Vue port can decide on purpose
whether to copy it or fix it. Each entry names the test that pins it.

| Where | What happens | Effect today | Pinned by |
| --- | --- | --- | --- |
| `dashboard/helper/actionQueryGenerator.js` | An automation action with `action_params: null` throws, because `typeof null` is `'object'`, so it takes the object branch. | Low: the UI sends `undefined` or a value, not `null`. | `helper/specs/moreHelpers.oneteam.spec.js` |
| `dashboard/helper/emailQuoteExtractor.js` | Quote-like text that is not inside a block element ("On … wrote:" in a bare `<span>`) makes `hasQuotes` say yes, but `extractQuotes` doesn't remove it, because the "block" found is the extractor's own wrapper. | Low: the "show quoted text" toggle can appear with nothing to hide. | `helper/specs/emailQuoteExtractor.oneteam.spec.js` |
| `dashboard/helper/AudioAlerts/DashboardAudioNotificationHelper.js` | `set()` without `audioAlertType` throws, because the default is an array but the code calls `.split` on it. | None today: every caller passes a string. | `helper/AudioAlerts/specs/DashboardAudioNotificationHelper.oneteam.spec.js` |
| `dashboard/store/modules/cannedResponse.js` | `deleteCannedResponse` sets `deletingItem: true` again when it finishes, on success and on failure, so the flag is never cleared. | Low: a "deleting" spinner bound to this flag would stay on. | `store/modules/specs/cannedResponses/cannedResponse.oneteam.spec.js` |
| `dashboard/store/modules/integrations.js` | `listAllSlackChannels` only clears `isFetchingSlackChannels` when the request fails, so after a successful listing the flag stays on. | Low: a loading state bound to this flag would not end. | `store/modules/specs/integrations/integrations.oneteam.spec.js` |
| `dashboard/components/widgets/WootWriter/utils/audioConversionUtils.js` | `convertToMp3` interleaves all channels into one sample array and passes it to lamejs as the left channel only. For a stereo recording lamejs then reads a missing right channel and throws, so the conversion fails with "Conversion to MP3 failed." | Medium: recordings are usually mono, but a stereo microphone (or Safari, which falls back to MP3) cannot send a voice note. The port should pass separate left and right arrays. | `dashboard/components/widgets/WootWriter/utils/specs/audioConversionUtils.oneteam.spec.js` |
| `widget/helpers/actionCable.js` | `onContactMerge` calls `ActionCableConnector.refreshConnector(pubsubToken)`, but no `refreshConnector` exists anywhere in Chatwoot, so a `contact.merged` event throws a `TypeError` inside the widget's socket handler. | Medium: when a visitor is merged into another contact (for example after identifying with an email that already exists), the widget keeps listening on the old pubsub token and stops getting live messages until the page reloads. The port should reconnect with the new token. | `widget/helpers/specs/actionCable.oneteam.spec.js` |
| `enterprise/app/services/captain/copilot/result_table.rb` | `escape` HTML-escapes cell text before Markdown-escaping it, so the tables Copilot's display tool returns show `&quot;`, `&amp;` and `&#39;` instead of the characters, for example in the filters line and in finding reasons. | Low: the model reads entities instead of quotes; links still work. The port can escape for Markdown only. | `spec/enterprise/services/captain/copilot/result_table_oneteam_spec.rb` |
| `spec/lib/integrations/slack/slack_link_unfurl_service_spec.rb` (Chatwoot's spec) | The unfurl examples hard-code account and conversation id 1 in their links. When the test database's ids differ, the service skips the links and the examples still pass, because they only check the return value. | None for users, but those examples test nothing on most runs. The overlay spec uses real ids. | `spec/lib/integrations/slack/slack_link_unfurl_service_oneteam_spec.rb` |
| `enterprise/app/services/captain/llm/translate_query_service.rb` | `query_in_target_language?` compares CLD3's language, a symbol such as `:fr`, with the account locale string `'fr'`, so it is never true. Every knowledge base search query is sent to the model for translation, even when it is already in the account's language. | Low: an extra model call per search, and the model usually returns the query unchanged. The port can compare strings. | `spec/enterprise/services/captain/llm/translate_query_service_oneteam_spec.rb` |
| `enterprise/app/services/voice/provider/twilio/recording_attachment_service.rb` | When Twilio sends a recording without a file name, the extension comes from `Rack::Mime::MIME_TYPES.invert`. Several extensions share `audio/mpeg`, and the inverted hash keeps the last one, so an MP3 recording is saved as `call-recording-RE….mpga`. | Low: browsers still play it from its content type, but the download has an unusual extension. The port can map `audio/mpeg` to `mp3`. | `spec/enterprise/services/voice/provider/twilio/recording_attachment_service_oneteam_spec.rb` |
| `enterprise/app/models/concerns/safe_endpoint_validatable.rb` | For a custom tool endpoint with no host (for example `https:/api`), `validate_not_ip_address` calls `include?` on a nil host, so saving the tool raises `NoMethodError` (a 500) instead of returning "must have a valid hostname". | Low: an admin typo gives a server error instead of a form error. The port can stop after the hostname error. | `spec/enterprise/models/concerns/safe_endpoint_validatable_oneteam_spec.rb` |
| `app/controllers/api/v1/accounts/portals_controller.rb` | `archive` calls `@portal.update(archive: true)`, but the column is `archived`, so Rails raises `ActiveModel::UnknownAttributeError` and the endpoint always returns 500. | Low: the dashboard doesn't call `PATCH /portals/:slug/archive` (it saves `archived` through the normal update). The port can set `archived` or drop the route. | `spec/controllers/api/v1/accounts/portals_settings_oneteam_spec.rb` |
| `lib/tasks/dev/variant_toggle.rake` | `chatwoot:dev:toggle_variant` and `chatwoot:dev:show_variant` guard with `return unless Rails.env.development?` inside the task block. Outside development that `return` raises `LocalJumpError` instead of doing nothing. | Low: a developer-only task; running it on a server prints a stack trace and changes nothing. The port can use an early `exit` or an Artisan command that only registers in local. | `spec/lib/tasks/dev/variant_toggle_oneteam_spec.rb` |
| `lib/test_data/database_optimizer.rb` | `setup` makes `conversations` and `messages` UNLOGGED, but `conversations` is now referenced by `conversation_monitor_evaluations`, so Postgres refuses with "could not change table "conversations" to unlogged because it references logged table". | Low: `rake data:generate_distributed_data` (a load-testing tool) stops before generating anything. The port can drop the UNLOGGED step or include the referencing tables. | `spec/lib/test_data_oneteam_spec.rb` |
| `app/services/conversations/unread_counts/filtered_count_invalidator.rb` | `previous_filter_type` and `previous_attribute_model` fall back to `raw.to_i`, and a non-numeric string becomes 0, so an unknown previous value is read as `conversation` (or `conversation_attribute`) instead of being kept as it is. | Low: Rails reports enum changes by name, so in practice the raw value is always a known name. The port can check for a numeric string before converting. | `spec/services/conversations/unread_counts/filtered_count_invalidator_previous_values_oneteam_spec.rb` |
